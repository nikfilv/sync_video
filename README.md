# Смотрим вместе / Sync Video

Первая версия расширения для синхронизации HTML5-видео прямо на исходных сайтах. Общие запуск, пауза, перемотка и скорость. Управлять могут оба участника. Видео каждый получает с самого сайта; сервер передаёт только состояние плеера.

## Быстрый запуск на одном компьютере

Нужен Node.js 20 или новее. Зависимостей для установки нет.

1. В папке проекта выполните `npm start`. Сервер запустится на `http://localhost:8787`.
2. Откройте `chrome://extensions` (Chrome), `edge://extensions` (Edge) или страницу расширений Яндекс Браузера. Включите режим разработчика и выберите «Загрузить распакованное расширение», указав папку `extension`.
3. После установки обновите уже открытые вкладки с видео.
4. Откройте одно видео в двух браузерах или разных профилях. Установите расширение в обоих.
5. В первом браузере нажмите значок расширения → «Создать комнату». Скопируйте код.
6. Во втором укажите тот же сервер, вставьте код → «Присоединиться».
7. Один раз нажмите Play в каждом браузере, если браузер блокирует автоматическое воспроизведение. Затем проверьте паузу и перемотку в обе стороны.

Подключение действует для выбранной вкладки, сохраняется при обновлении страницы и завершается при закрытии вкладки или перезапуске браузера. Отдельные вкладки можно подключать к разным комнатам.

## Два компьютера

`localhost` означает тот компьютер, на котором открыт браузер. На разных компьютерах нужно указать адрес **одного общего сервера**.

Для домашней сети запустите сервер с прослушиванием сетевого интерфейса (PowerShell):

```powershell
$env:HOST = '0.0.0.0'
npm start
```

Укажите в обоих расширениях `http://IP-КОМПЬЮТЕРА-С-СЕРВЕРОМ:8787`. Доступ к порту 8787 должен быть разрешён в брандмауэре для вашей частной сети. Сам проект не меняет брандмауэр.

Для разных сетей разместите Node-сервер на доступном обоим хосте за HTTPS reverse proxy. Прокси должен сохранять путь запроса и иметь тайм-аут больше 25 секунд: сервер использует long polling. Задайте `HOST=0.0.0.0` и при необходимости `PORT`. Участники вводят одинаковый HTTPS адрес сервера. Развёртывание в интернете в эту версию не входит.

## Поддержка и ограничения

- Целевая платформа: настольные Chromium-браузеры, Manifest V3, Chrome 116+. Firefox и мобильные браузеры в этой версии не поддерживаются.
- Используется стандартный элемент `<video>`, включая доступные расширению вложенные HTTP/HTTPS фреймы. В каждой вкладке выбирается самое большое видимое видео. Для страниц с несколькими плеерами выбор может потребовать доработки.
- YouTube рассчитан на управление через его HTML5-плеер. Рекламные сегменты с классами `ad-showing` / `ad-interrupting` исключаются; после рекламы расширение пытается восстановить позицию. Реальную совместимость с YouTube и другими сайтами нужно проверить вручную: сайты меняют плееры.
- Закрытый Shadow DOM, защищённые страницы браузера и нестандартные плееры не поддерживаются. Платные сервисы, DRM и различающаяся реклама могут мешать работе; подписка и доступ к видео нужны каждому отдельно.
- Оба участника должны открыть одну ссылку. Для YouTube сравнивается ID ролика; для других сайтов — адрес страницы без метки `#` и распространённых рекламных параметров. Адреса с разными значимыми параметрами считаются разными видео.
- Для прямых трансляций с разными временными шкалами синхронизация не гарантируется. Первая версия рассчитана на обычные записи.
- Это синхронизация положения плеера с коррекцией отклонений, а не покадровая синхронизация. Буферизация одного участника не ставит автоматически второго на паузу.
- Браузер может требовать ручное нажатие для воспроизведения со звуком; расширение показывает подсказку. Сворачивание вкладок и режим энергосбережения могут увеличивать задержку.

## Как устроено

- `extension/popup.*` — создание комнаты, подключение и отключение текущей вкладки.
- `extension/content.js` — поиск плеера, отслеживание событий, применение удалённого состояния и коррекция отставания.
- `extension/background.js` — запросы к серверу от имени расширения, выбор фрейма, последовательная отправка команд и хранение подключений в `chrome.storage.session`.
- `server/index.js` — HTTP API без внешних зависимостей. Long polling до 20 секунд передаёт изменения сразу после получения. Последний участник, изменивший плеер, становится источником периодических уточнений позиции.

Комнаты существуют только в памяти сервера и исчезают при его перезапуске или после 24 часов неактивности. Код комнаты — случайный 96-битный секрет: любой, кто его получил, может присоединиться и управлять воспроизведением. Отдельной регистрации нет.

Расширение запрашивает доступ к HTTP/HTTPS сайтам, чтобы находить плееры и обращаться к указанному серверу. Вне подключённой комнаты состояние видео не отправляется на сервер. При подключении передаются код комнаты, случайный ID клиента, положение, скорость, пауза и идентификатор видео (для обычного сайта — URL страницы). Не используйте приватные ссылки с токенами на недоверенном сервере. Для публичного размещения используйте HTTPS: обычный HTTP не шифрует код комнаты и команды.

## Проверка

```powershell
npm run check
npm test
```

Автотесты проверяют API между клиентами, изоляцию комнат, паузу/перемотку/скорость, позднее подключение, отклонение некорректных запросов, long polling, смену управляющего и логику видеоскрипта с моделью плеера. Они не заменяют проверку настоящего сайта в браузере.

Ручная проверка: два профиля → одна комната → один ролик → запуск, пауза и перемотка с каждой стороны → смена скорости → обновление вкладки → остановка и повторный запуск сервера → повторное создание комнаты. Отдельно проверить рекламу и плеер во вложенном фрейме.
